# 「我的食物库」设计

日期：2026-11-22　状态：已实施（2026-11-22，在 iPhone 17 模拟器里验证，见第 10 节）　依据：负责人 2026-11-21 提出的想法（需求文档 v2.1 里没有这一项）

## 1. 目标

用户把平时想吃的、常吃的食物收进一个自己的库，用图片网格显示，随时一键加进当天的记录。

**为什么要做**：现在「常吃 / 最近吃过」和「我的餐」都藏在「+ 添加」后的搜索页里，而且「常吃」是系统按记录算的，用户不能自己决定放什么；「想吃但还没吃过」的食物没有地方放。底部「食物库」有图片网格，但内容是固定的 57 种。

**不做什么**

- 不新开底部标签，不新开页面
- 不把系统算出的「常吃」自动放进来（负责人 2026-11-22 定：只放用户自己收藏的）
- 搜索页的「常吃 / 最近吃过 / 我的餐」保持原样
- 不给收藏的食物配新图片
- 自己建的食物不会自动进「我的」，和别的食物一样要点收藏（沿用「只放用户自己收藏的」这个决定）

**做坏了的样子**：页面变复杂、文字变多；用户分不清「我的」「常吃」「我的餐」；点「＋」之后不知道加到了哪一餐。

## 2. 考虑过的做法

| 做法 | 取舍 | 结论 |
|---|---|---|
| A. 在「食物库」分组最前面加「我的」，食物页加「收藏」 | 复用现成的网格和食物页；多一张表、三个接口 | **采用**（负责人 2026-11-22 同意） |
| B. 底部新开一个标签 | 入口最显眼；但底部已有同名的「我的」（个人资料），多一个标签页面更复杂 | 不采用 |
| C. 不做收藏，把「常吃」搬到食物库 | 不用改数据库；但「想吃的」放不进来，内容也不是用户选的 | 不采用 |

## 3. 数据

新表 `favorite_foods`（迁移 `0007`，新建表，不改已有表）：

| 列 | 说明 |
|---|---|
| `user_id` | 外键 → `user`，用户删除时一起删 |
| `food_id` | 外键 → `foods`，食物删除时一起删（自定义食物被删后收藏自动消失） |
| `created_at` | 收藏时间 |

主键是（`user_id`，`food_id`），所以同一个食物不会收藏两次。

「我的餐」沿用 `meal_templates`，不改。

## 4. 接口

- `PUT /api/foods/:id/favorite` → 204。已经收藏过再收藏也是 204。食物不存在或是别人的自定义食物 → 404
- `DELETE /api/foods/:id/favorite` → 204。本来没收藏也是 204
- `GET /api/foods/favorites` → `{ foods }`，最新收藏的排在前面。每项是普通的食物摘要，另加：
  - `libraryKey`：有就显示食物库的图
  - `slot`：盘子的哪一格（没有图时用它的颜色）
  - 一键添加用的份量：`portionId`、`portionLabel`、`quantity`、`grams`、`kcal`（这个份量的热量）。规则：
    - 吃过的：用最近一次记录的份量（和「常吃」的规则一样，见 `getRecentFoods`）。按份量记的，克数按这个份量**现在**的重量 × 份数算（重新导入或编辑自建食物会改份量的重量，添加时用的是现在的重量）
    - 没吃过的：用食物页打开时预选的份量，即第一个份量 × 1；没有份量的食物是 100 克
- `GET /api/foods/:id` 增加 `favorite: boolean`

路由要写在 `'/:id'` 前面（和 `mine`、`library` 一样），否则 `favorites` 会被当成食物 id。

## 5. 页面

### 5.1 食物库标签

```
食物库
你收藏的食物和存下的餐，点 ＋ 加到今天
[我的] [碳水] [蛋白质] [脂肪] [蔬菜] …

┌────────┐ ┌────────┐ ┌────────┐
│  🥚  ＋│ │  🍚  ＋│ │  鸡   ＋│
│ 水煮蛋 │ │ 白米饭 │ │ 鸡胸肉 │
│100克·156│ │150克·195│ │100克·165│
└────────┘ └────────┘ └────────┘

我的餐
 鸡胸肉 + 白米饭 + 西兰花                    ＋
 3 样 · 520 千卡
```

- 分组标签最前面加「我的」。打开食物库时：有收藏或有「我的餐」就先显示「我的」，否则和现在一样先显示「碳水」
- 选中「我的」时，标题下面那一行不写「按营养特点分组，数值都是每 100 克」（这一组的数值是按份量算的），改写这一组自己的一句说明；分组标签下面不再另起一行。这样切换分组时标签不会上下跳
- **收藏的食物**：三列网格，和其他分组同样的小块
  - 图：食物库里有图的用原图；没有图的（搜索来的、自己建的）显示一个圆，颜色是它在盘子里那一格的颜色，中间是名字的第一个字
  - 名字：有图的用食物库的简短名；其他的用中文名去掉末尾括号；没有中文名的（USDA 大部分食物）用英文名。最多两行，放不下就截断
  - 第三行：克数和热量，如「100 克 · 156 千卡」，放不下时缩小字号。只写克数，不写「2 × 1 large」这种份量：USDA 的份量名是英文而且很长，小块里放不下
  - 点小块：进食物页（和其他分组一样），可以改份量、改餐次、取消收藏
  - 点右上角「＋」：按第 4 节的份量（就是第三行那个克数）直接加到**今天**、按当前时间预选的那一餐（规则同 `mealAt`）。加完「＋」变成「✓」，屏幕底部（标签栏上方）浮出一条「已加到午餐：水煮蛋」，3 秒后自己消失。浮条不跟着列表滚动，所以收藏多、加的是下面的小块或「我的餐」时也看得到；也不占列表的位置，不会把小块往下推。可以连续加几样不同的。失败时浮条显示报错（走 `failureText`），停 6 秒，小块保持「＋」
  - 「✓」保持 3 秒，这期间再点不会重复添加，之后恢复成「＋」，可以再加一份。原因：在模拟器里快速连点两下会记成两条；而如果「✓」一直保持到离开页面，App 放在后台、第二天再打开时「＋」还是失效的。离开食物库时「✓」和浮条都立即清掉
- **我的餐**：放在网格下面，一行一个（名字是「鸡胸肉 + 白米饭 + …」，放不进小块）。每行右边有和小块一样的圆形「＋」，点它才添加，点这一行别的地方没有反应：整行都能点的话容易误加一整餐。加完显示同样的「已加到午餐：…」。没有存过的餐时，这一段整个不显示
- **没有收藏时**：网格的位置显示一句「还没有收藏。在任意食物的页面点「☆ 收藏」，它就会出现在这里」。有「我的餐」的话照常显示在这句话下面；没有就只有这句话

### 5.2 食物页

- 名字下面加一个「☆ 收藏」；已收藏时显示「★ 已收藏」，再点一次取消。所有食物都有（USDA、食物库、自己建的）
- 点了立刻变，不用等服务器；服务器失败时变回去并显示报错
- 「加到某一餐」按钮和其他内容不变

## 6. 文字

新增的文字都放进 `zh.ts` 和 `en.ts`，键一致。语气中立，不出现「推荐」之类的词。中文暂定：

| 用在哪 | 文字 |
|---|---|
| 分组名 | 我的 |
| 分组说明 | 你收藏的食物和存下的餐，点 ＋ 加到今天 |
| 空状态 | 还没有收藏。在任意食物的页面点「☆ 收藏」，它就会出现在这里 |
| 加完提示 | 已加到{meal}：{food} |
| 食物页 | 收藏 / 已收藏 |

## 7. 留给实现的人决定

- `favorite_foods` 的索引、接口返回字段的具体类型
- 「＋」「✓」和圆形占位图的具体尺寸、样式（跟现有 `tokens` 走）
- 「已加到…」那一行停留多久（实施时定为 3 秒，报错 6 秒）
- 食物页「收藏」放在名字下面的哪一行、用哪个图标

## 8. 范围外

- 收藏数量上限、排序、分组、搜索
- 在网格里长按取消收藏（只能进食物页取消）
- 在食物库里删除「我的餐」（删除入口保持原样）
- 把「常吃」「最近吃过」合并进来

## 9. 测试

- api：
  - 收藏、重复收藏、取消、取消没收藏过的
  - 收藏别人的自定义食物 → 404；列表里只有自己的收藏
  - 删除自定义食物后收藏消失
  - 份量：吃过的用最近一次的；没吃过的用第一个份量 × 1 或 100 克
  - `GET /api/foods/:id` 的 `favorite`
- mobile（纯函数）：打开时先显示哪一组；小块的名字和第三行的文字；没有图时取哪个字；`zh.ts` 和 `en.ts` 的键一致
- 模拟器：收藏 → 出现在「我的」→ 点「＋」→ 今日页里有这条记录；取消收藏后消失；空状态；英文界面

## 10. 实施记录（2026-11-22）

**自动测试**：api 107 个、mobile 129 个全部通过；`pnpm typecheck` 通过。

**在模拟器里看过的**

- 没有收藏时食物库先显示「碳水」，「我的」里是那句提示
- 在食物页点「☆ 收藏」变成「★ 已收藏」，再点一次取消，回到「我的」后这个食物消失
- 「我的」里三种小块：有图的、没有图的（圆形加首字母）、名字两行的英文食物；一行里的小块一样高
- 点「＋」：变成「✓」，今日页多出这条记录；连点三下只记一条
- 代码审查后的修改：点「＋」后底部浮出「已加到加餐：水煮蛋」，约 3 秒后浮条消失、「✓」变回「＋」
- 「我的餐」一行和它的「＋」，加完后今日页多出这一餐的食物
- 吃过以后，小块上的克数变成最近一次记录的克数
- 关掉 API 再点「＋」：显示「没能添加：出了点问题，请稍后再试」，小块保持「＋」
- 有收藏时，重新打开 App 后食物库先显示「我的」
- 英文界面

**没有在屏幕上看过的**

- 有「我的餐」但没有收藏的账号（提示在上、「我的餐」在下）
- 没同意健康数据的账号点「＋」（代码走的是和别处一样的 `failureText`）
- 收藏了自己建的食物以后的小块

**实施时改掉的设计**（原因都写在上面对应的条目里）：「我的」的说明放在标题下面；「我的餐」每行加「＋」。

**代码审查后改掉的**：「已加到…」从标题下面移到底部浮条（原来的位置在收藏多时会滚出屏幕）；「✓」从「整次访问」改成 3 秒；份量按现在的重量算克数（原来用旧记录的克数，和实际记下的可能不一样）。
