# 个人主页「我的」设计

日期：2026-11-02　状态：实施中　依赖：第二阶段「食物库」

## 1. 目标

App 底部加标签栏「今日 / 我的」。「我的」集中放个人信息与设置，今日页只保留饮食日记。

## 2. 页面内容（自上而下）

| 区块 | 内容 |
|---|---|
| 账号 | 头像（昵称首字）、昵称（可修改，1–40 字）、邮箱 |
| 身体资料与目标 | 年龄、性别、身高、体重（按用户的单位显示）、目标与速度、BMI；每日热量与三大营养素；「重新填写问卷」 |
| 记录统计 | 记录天数、连续记录天数、记录条数 |
| 我的自定义食物 | 自己添加的食物列表（最近修改的在前），点进去可记录、编辑、删除；「添加自定义食物」 |
| 设置 | 语言、单位（公制 / 英制）、退出登录 |

## 3. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/foods/mine` | 自己的自定义食物，按修改时间倒序 |
| GET | `/api/diary/stats?today=YYYY-MM-DD` | `{ loggedDays, currentStreak, totalEntries }` |
| PATCH | `/api/me/settings` | `{ unitSystem?, locale? }`，只改资料里的这两项，不生成新的目标版本 |
| POST | `/api/auth/update-user` | Better Auth 自带；在注册前钩子旁加校验，昵称须为 1–40 字 |

**连续记录天数**：从 `today` 往前数，连续每天都有记录的天数；今天还没记录时从昨天开始数（当天还没吃饭不算断）。`today` 由 App 传用户本地日期（服务器不知道用户时区），只统计不晚于 `today` 的日期。计算放在 `packages/core`（`currentStreak`），日期加减函数 `shiftDate` 也移到 core，App 与后端共用。

## 4. 语言与单位

- 切换语言或单位时调用 `PATCH /api/me/settings` 保存。
- 登录后读取资料时应用已保存的语言，解决第一阶段遗留的「语言选择没有保存」。
- 单位只影响显示（个人主页的身高体重、重新填写问卷时的默认单位）；存储与计算仍然只用公制。

## 5. 路由

`today` 与 `me` 放进 `(tabs)` 分组（URL 仍是 `/today`、`/me`），守卫与原来的 `today` 相同。食物与记录页面仍然压在标签页之上。「重新填写问卷」的入口与结束编辑的逻辑从今日页移到「我的」。

## 6. 范围外

头像上传、修改邮箱或密码、注销账号、按周 / 月的趋势图（第五阶段）。
