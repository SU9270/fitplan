# 报错文案设计

日期：2026-11-03　状态：已实施

## 1. 目标

以前所有请求失败都显示「…，请检查网络后重试」，但很多失败跟网络没关系（比如服务器还是旧版本、少了接口）。现在报错要说清楚是**哪一步**没成功、**为什么**，开发时还要能在终端里看到细节。

## 2. 文案

格式统一为「{哪一步}：{原因}」，例如「没能复制：App 和服务器的版本不一致，请更新 App（开发时请重启 pnpm dev）」。

| 原因 | 判断 | 文案 |
|---|---|---|
| 网络 | 请求没发出去（`fetch` 抛出 `TypeError`） | 连不上服务器，请检查网络后重试 |
| 服务器出错 | 5xx | 服务器出错了，请稍后再试 |
| 版本不一致 | 404 且不是 JSON（Hono 找不到路由时返回纯文本，说明服务器上没有这个接口） | App 和服务器的版本不一致，请更新 App（开发时请重启 pnpm dev） |
| 内容不存在 | 404 且是 JSON（我们的接口找不到记录时返回 `{ code: 'not_found' }`） | 这条内容已经不存在了 |
| 输入不对 | 400、422 | 有内容没通过检查，请修改后重试 |
| 需要同意 | 403（只有「未同意健康数据使用」会返回） | 需要先同意使用健康数据（问卷最后一步） |
| 其他 | 其余情况 | 出了点问题，请稍后再试 |

- 401 不显示报错：和以前一样，直接退出登录回到登录页
- 删除时「内容不存在」算删除成功
- 食物详情页找不到食物时仍显示「这个食物已经不存在了」，不显示重试按钮

## 3. 实现

`apps/mobile/src/lib/request.ts`：

- `call(action, send)`：发请求并分类，返回 `ok`（带响应）、`failed`（带 `{ action, problem }`）或 `signedOut`
- `failureText(failure, t)`：拼出「{哪一步}：{原因}」
- 失败时用 `console.warn` 打出动作、状态码、原因和地址，在运行 `pnpm dev` 的终端（Metro）里能看到

所有页面的请求都改用 `call`；昵称走 Better Auth 客户端，按它返回的状态码用同样的规则分类。搜索页的「最近 / 常吃 / 我的餐」读取失败时仍不提示（没有它们只是普通的搜索页）。
