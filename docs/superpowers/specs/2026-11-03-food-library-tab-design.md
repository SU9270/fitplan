# 食物库标签页设计

日期：2026-11-03　状态：已实施（用真实 SR Legacy 数据验证）　依据：需求文档 v2.1 §3.4

## 1. 目标

底部加一个「食物库」标签：常见食物配上统一风格的图片，按营养特点分组，用户可以浏览「哪些食物是碳水 / 蛋白质 / …」，点进去就能记到某一餐。

## 2. 分组

一种食物可以出现在多个组里（如牛油果：脂肪、水果、高纤维）。分组全部按规则从营养数据算出（`packages/core` 的 `libraryGroups`），不手工标注：

| 组 | 规则 |
|---|---|
| 碳水 | 盘子归「主食」：碳水提供的热量多于脂肪（含土豆、红薯、玉米等淀粉类蔬菜和豆类） |
| 蛋白质 | 盘子归「蛋白质」：蛋白质提供至少 30% 的热量；盘子归「其他」但蛋白质达到 30% 的也算（蛋白粉在 USDA 里属于饮品） |
| 脂肪 | 脂肪提供至少 50% 的热量，且不在蛋白质组（鸡蛋、三文鱼留在蛋白质组） |
| 蔬菜 | 盘子归「蔬菜」 |
| 水果 | USDA 分类为水果 |
| 高纤维 | 膳食纤维 ≥ 6 g / 100 g（GB 28050-2011「高或富含膳食纤维」） |
| 富含 Omega-3 | ALA ≥ 0.6 g，或 EPA + DHA ≥ 80 mg，每 100 g 和每 100 kcal 都要达到（欧盟 1924/2006「high omega-3」；国标没有 Omega-3 的声称） |

**不设「抗炎」组**：需求文档 §3.4 规定不使用「抗炎」「超级食物」等定义模糊的标签。常被归为「抗炎」的食物（深海鱼、坚果、亚麻籽、深色蔬果）分别出现在「富含 Omega-3」「高纤维」「蔬菜」「水果」里，用的是可以核对的营养事实。

每组顶部用一句话写明规则；每个食物下面显示这一组关心的那个数值（蛋白质组显示蛋白质克数，蔬菜和水果显示热量，Omega-3 组显示 EPA+DHA 毫克或 ALA 克，哪个多显示哪个）。

## 3. 数据

- 食物库的食物在 `apps/api/data/usda-zh.csv` 新增的 `library` 列里标出，值是图片文件名（小写字母、数字、下划线，不能重复）；行的先后就是显示顺序。首批 57 种：主食 / 薯类 / 豆类 12、肉蛋鱼豆制品 16、蔬菜 12、水果 10、坚果种子油 7；新加了沙丁鱼罐头、亚麻籽、奇亚籽三行
- `foods` 新增列：`omega3_ala_g`、`omega3_epa_dha_g`、`library_key`（唯一）、`library_rank`，都用 `ADD COLUMN`
- 导入：ALA 取 FDC 营养素 1404（18:3 n-3 c,c,c），没有时取 1270（18:3 总量，植物性食物里几乎全是 ALA）；EPA（1278）和 DHA（1272）相加
- 重新导入前先清空所有 USDA 食物的 `library_key`，这样把文件名换到另一种食物上也不会撞唯一约束
- 加了新列以后要**重新运行一次 `food:import`**，`pnpm dev` 发现食物库为空时会提示

## 4. 接口

- `GET /api/foods/library` → `{ foods }`：按 `library_rank` 排序，每项是普通的食物摘要，加上 `key`、`groups`、`fiberG`、`omega3AlaG`、`omega3EpaDhaG`
- `GET /api/foods/:id` 增加 `libraryKey`，食物详情页据此在顶部显示图片

## 5. 页面

- 底部标签：今日 · 食物库（菜篮子图标）· 我的
- 标题、说明（「按营养特点分组，数值都是每 100 克」）、可横向滑动的分组标签、这一组的规则说明、三列图片网格（白色小块放在灰色卡片里，与其他页面一致）
- 网格里的名字去掉括号里的注释（「鸡胸肉（烤）」显示为「鸡胸肉」），详情页仍显示全名；英文界面用文件名拼出简短名称（USDA 英文名太长）
- 点一个食物进入食物详情，日期是今天，餐次按当前时间预选（10 点前早餐、14 点前午餐、17 点前加餐、21 点前晚餐、之后加餐），可以在详情页改

## 6. 图片

- 每个食物一张正方形 PNG：`apps/mobile/assets/library/<key>.png`，在 `apps/mobile/src/library/images.ts` 里登记（React Native 需要静态 `require`）
- 现在是占位图：微软 Fluent Emoji 3D（MIT 协议，许可证放在同一文件夹）。正式的图由团队用 AI 按统一提示词生成，替换同名文件即可，步骤和清单见 `docs/food-library-images.md`
- 服务器上有、App 里还没有图的食物显示一个通用图标

## 7. 测试

- core：每个组的规则与边界（6 g 纤维、80 mg EPA+DHA、ALA 的每 100 kcal 条件、鸡蛋和三文鱼不进脂肪组、蛋白粉进蛋白质组、营养缺失）
- api：`library` 列的解析与校验、Omega-3 导入、库标记的导入与移动、`GET /api/foods/library` 的排序与分组、详情的 `libraryKey`
- mobile：按时间预选餐次、简短名称、每组显示的数值；图片文件、`images.ts` 与 csv 三处的文件名一致
- 用真实数据检查：57 种食物都至少进一个组（碳水 12、蛋白质 16、脂肪 8、蔬菜 12、水果 10、高纤维 9、Omega-3 9）
